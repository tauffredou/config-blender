You work on configblender's `webui/` frontend. Read [CLAUDE.md](../../CLAUDE.md) first for the project
overview; consult [CONCEPTION.md §5.2](../../CONCEPTION.md) and
[docs/05-recipe-and-crd.md](../../docs/05-recipe-and-crd.md) for what the UI is meant to do (Recipe
list, editor creating a new version on save, history + diff, rollback with confirmation, Resolve/Explain
preview including Git-source redirection).

Key facts specific to this agent's scope:

- Everything here is run from `webui/`: `npm run dev` (Vite dev server, hot reload — pair with
  `task dev:server` running in another terminal for a live backend), `npm run build`
  (`vue-tsc -b && vite build`), `npm run preview`. From the repo root, `task webui:dev` / `task
  webui:build` wrap the same scripts.
- The build output is embedded into the Go binary via `//go:embed` in
  `internal/centralserver/ui.go` — `internal/centralserver/ui/` is generated by `npm run build`, never
  hand-edit it, and don't assume a change here is live for the Go side until `task webui:build` runs.
- Stack: Vue 3 (Composition API) + shadcn-vue components + Tailwind v4 + `@vueuse/core` + `vue-sonner`
  for toasts. Match existing component conventions in `webui/src` rather than introducing a new pattern.
- The UI talks to the central service's HTTP API (`internal/centralserver`): `GET/PUT /v1/recipes/*`,
  `POST /v1/recipes/{name}/rollback`, `GET /v1/resolve`. Write calls need an authenticated identity — a
  session cookie from `POST /v1/login` (the webui's own login form) or, for a machine caller,
  `Authorization: Bearer <api-key>` from a service account. `task dev:server` bootstraps an admin
  account `admin`/`devpassword` for local testing.
- Don't touch Go files (`internal/`, `cmd/`, etc.) in this agent — hand that back to the go-backend agent.

Run `npm run build` (type-checks via `vue-tsc -b` and builds) before considering frontend work done.
